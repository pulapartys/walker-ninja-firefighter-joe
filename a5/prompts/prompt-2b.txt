The only soft spot is R6: the game's own pause (`set_paused`) is not a tree pause. ## Step 1: driver and hook

New file `godot/features/player/hose_glow.gd`, `extends Node`, about 25 lines:

- Constants `SHADER := preload("res://shaders/hose_glow.gdshader")`, `PARAM := "glow"`, `RAMP_SECONDS := 0.25`. State `var glow := 0.0`, `var material: ShaderMaterial`.
- `_ready()`: `material = ShaderMaterial.new()`, `material.shader = SHADER`, `get_parent().sprite.material = material`, write `glow` 0.0. One material per player instance, created here (R8, F5: it goes on `player.sprite` only).
- `_process(delta)`: `target = 1.0 if get_parent().hosing else 0.0`, `glow = move_toward(glow, target, delta / RAMP_SECONDS)`, `material.set_shader_parameter(PARAM, glow)`. Reads `player.hosing`, writes one parameter, nothing else (R1, R2, R3, R4, R7 by construction). `_process` runs after the physics ticks of the same frame, so it sees the fresh `hosing` value.

Hook in `godot/features/player/player.gd` `_ready()`, after the sprite is created: three lines that instance the driver and `add_child` it. No physics, input or tuning lines touched. `session.gd` is not edited. The material survives texture swaps in `show_pose` because it is a CanvasItem property, so the glow also tints the run pose during the +60 linger if he walks off early, which is the "water is on" meaning the brief wants.

## Step 2: new headless test `godot/tests/test_hose_glow.gd`

`extends SceneTree`, same `fresh()` / `steps()` / `check()` shape as `test_game.gd`, with `test_control` left false so the session reads real Input. A `Sampler` node on root with `process_priority = 100` records, every `_process`, the pair of `player.sprite.material.get_shader_parameter("glow")` and `delta`. W and R presses are synthetic `InputEventKey` taps through `Input.parse_input_event`, the path `test_keyboard.gd` already proves reaches `is_action_just_pressed` in physics headlessly. The test never calls the driver or touches its fields.
